Microsoft Confidence Gate

Speaker Attribution Setup Evaluation

Task & Data

Research Question:
Can we identify internal model signals that distinguish reliable from unreliable speaker-attribution decisions, and use them to build a confidence gate that outperforms output probability alone?

Task

Given:

  • a transcript window/chunk with anonymized speaker labels,
  • one target speaker (e.g. Speaker 2),
  • and a candidate list mapped to neutral IDs (A, B, C, ...),

Predict which candidate corresponds to the target speaker.

Output: exactly one candidate ID or UNKNOWN.

Data

The dataset is constructed around attribution evidence events. We scan meeting transcripts for moments that provide evidence about the identity of an anonymous speaker, and manually validate that each event clearly identifies one target speaker.

Accepted evidence includes 3 types:

  • self_identification;
    Example

    Speaker 2: “Um so first of all my name is Shoval…”

  • direct_greeting_or_call followed by the target’s response;
    Example

    Speaker 1: “Hello, Shoval.”

    Speaker 2: “Hello.”

  • direct_question_request_or_invitation followed by the target’s response.
    Example

    Speaker 3: “So Sunny, how do you calculate the latency?”

    Speaker 2: “Yeah basically for the bot side…”

Matched counterfactual pairs

Each validated evidence event is then used to construct a matched counterfactual pair of model inputs:

Input Example Ground truth
Evidence Speaker 1: “Hi, Shoval.”
Speaker 2: “Hi.”		 Shoval
No-evidence Speaker 1: “Hi, everyone.”
Speaker 2: “Hi.”		 UNKNOWN

The pair therefore represents the same attribution situation, with the identifying evidence present in one input and removed in the other.

We report evidence outcomes as correct attribution, wrong attribution, or missed attribution; no-evidence outcomes are correct rejection or false attribution.

Data sources

  • Real meetings human transcripts: 291 matched pairs cmdlabsildata/meeting-ai-datasets/TeamsLiveMeetingData_FY25/en-US/
  • Synthetic transcripts: 400 matched pairs from 400 distinct meetings, cmdlabsildata/datasets/Synthetics2_7/en-US

Real: 291 pairs from 305 accepted evidence events. Synthetic: 400 pairs, evenly split between greeting/call and question/request evidence.

Confidence Gate Evaluation

Gate is trained on:

Label 1:
Correct attribution
Label 0:
Wrong attribution
False attribution

We evaluate the gate using:

  • TPR: Of all correct attributions, how many passed the gate.
  • FPR: Of all wrong and false attributions, how many passed the gate.
  • AUROC: How well the gate separates Label 1 from Label 0 across thresholds.

Targets

  • Attribution required (evidence)
    • Correct-attribution rate ≥30%
    • Wrong-attribution rate ≥30%
    • Missed-attribution rate ≤40%
  • Probability should remain a weak confidence baseline
    • AUROC <0.8
    • FPR at approximately 90% TPR ≥70–80%
  • No attribution required (no evidence)
    • False-attribution rate ≈20–30%
    • Correct-rejection rate ≈70–80%
  • Data sufficiency
    • Enough golden counterfactual pairs for circuit discovery
    • Enough correct and wrong non-UNKNOWN predictions for gate training

Each rate uses only the examples from its corresponding type.
